# 사례: 평가셋이 점수를 부풀리고 있었다

비공개 프로젝트에서 가장 중요했던 발견이다. 아래 수치는 협회 자료로 측정한 결과이고, 이 데모에서는 재현되지 않는다(자료가 포함되지 않는다).

## 1. 의심의 시작

검색 방식 비교에서 "저장된 질문과 매칭"하는 방식(`question`, `both`)이 holdout 1위 정답률을
**56.7% → 81.1%**로 크게 올렸다. 채택하기 쉬운 결과였다.

그런데 평가셋의 답 있는 문항 대부분이 **문서에 저장된 질문을 LLM이 표현만 바꿔 쓴 것**이었다. 저장된 질문과 매칭하는 방식이 유리할 수밖에 없는 구조이고, 개선이 진짜인지 오염인지 구별할 수 없었다.

## 2. 사전 등록

결과를 보기 전에 규칙을 먼저 커밋했다. 저장된 질문을 **보지 못한** 작성자가 답변 본문만 보고 60문항을 쓰고, 그 세트에서 세 방식을 다시 잰다. 어느 방식이 이기면 채택하는지도 미리 적었다.

## 3. 결과가 뒤집혔다

| 방식 | 1위 정답률 (오염 없는 60문항) |
|---|---|
| `answer` (본문 매칭) | **81.7%** |
| `question` | 60.0% (`answer`와의 차이 p = 0.011) |
| `both` | 76.7% |

큰 개선은 평가셋이 만든 착시였다. 규칙에 따라 `answer`가 유지됐다.

## 4. 반대 방향 편향도 점검했다

답변 본문을 보고 쓴 문항이니 본문 매칭이 유리한 건 아닌가. 질문-본문 어휘 겹침이 기존 문항과 같은 수준이라는 것을 측정해 확인하고 이 가능성을 기각했다(0.066 대 0.064).

## 5. 평가셋을 고쳤다

정답 문항 130건을 같은 방식(답변 본문만 보고)으로 다시 썼다. 그러자 같은 시스템의 holdout 1위 정답률이 **56.7% → 66.7%**로 올랐다. 이 경우에는 평가셋이 시스템을 **실제보다 나쁘게** 보이게 하고 있었다. 평가셋의 오염은 한쪽으로만 편향되지 않는다는 것을 발견했다.

## 6. 실제 주제 세트에서 리랭크를 평가했다

작성형 평가셋과 실제 검색 기록 기반 평가셋은 질문을 만든 방식과 평가 문항이 다르므로, 두 세트의 점수를 직접 비교하지 않는다. 상담원에게 초기 버전을 제공해 얻은 검색 기록으로 만든 실제 주제 세트(답이 있는 문항 211건)에서 임베딩 상위 문서를 LLM으로 재정렬한 뒤, 최종 검색 순위 지표는 **1위 정답률 68.2%**(144/211), **Recall@5 84.4%**(178/211)였다.

## 이 사례에서 얻은 규칙

- 큰 개선이 나오면 채택하기 전에 측정 도구를 먼저 의심한다.
- 판정 규칙은 결과보다 먼저 커밋한다.
- 같은 사람이 문서와 문항을 함께 쓰면 점수는 증거가 아니다. **이 데모의 평가셋이 바로 그런 경우**라서, 데모의 점수는 방법이 돌아간다는 표시일 뿐이다.
